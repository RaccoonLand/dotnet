# 1. SqlAuthorizationOptions

Externally supplied settings for the SQL Server authorization provider. The provider keeps **no** rules of its
own: it asks two configurable stored procedures for the set of anonymous request names and the set of request
names the current user may execute.

- **Package:** `RaccoonLand.Modules.Security.Authorization.SqlServer`
- **Namespace:** `RaccoonLand.Modules.Security.Authorization.SqlServer.Configuration`

## Members

| Member | Default | Description |
| --- | --- | --- |
| `ConnectionString` *(required)* | — | Connection string to the database hosting the procedures. |
| `ServiceName` | `""` | Optional microservice name. When set, passed to both procedures and included in cache keys. |
| `ApplicationName` | `""` | Optional application name within the service. Same semantics as `ServiceName`. Prefer setting both together for a shared AuthZ store. |
| `AnonymousRequestsProcedure` *(required)* | — | Procedure returning the anonymous request full-names. |
| `AllowedRequestsProcedure` *(required)* | — | Procedure returning the request full-names allowed for a user; receives the user id (and optional scope). |
| `UserIdParameterName` | `UserId` | Parameter name (without `@`) passed to `AllowedRequestsProcedure`. |
| `ServiceNameParameterName` | `ServiceName` | Parameter name used when `ServiceName` is non-empty. |
| `ApplicationNameParameterName` | `ApplicationName` | Parameter name used when `ApplicationName` is non-empty. |
| `CommandTimeoutSeconds` | `30` | Command timeout applied to each stored-procedure call. |
| `EnableCache` | `false` | Cache the resolved sets in `IDistributedCache`. Requires a registered distributed cache. |
| `CacheKeyPrefix` | `raccoonland:authz:` | Prefix applied to every cache key. |
| `AnonymousCacheDuration` | `00:05:00` | Lifetime of the cached anonymous set. |
| `UserCacheDuration` | `00:01:00` | Lifetime of each user's cached allowed set. |

## Microservice scope (optional)

Leave `ServiceName` / `ApplicationName` empty for a dedicated per-service database (current default).

When many microservices share one authorization database (or one Redis for `EnableCache`), set both — similar to
`MessageLocalization`'s service/application isolation, but **optional**. Scoped values are:

1. Passed only when non-empty (so existing unscoped procedures keep working).
2. Embedded in cache keys as `svc:{ServiceName}|app:{ApplicationName}` so shared Redis cannot cross-contaminate allow-lists.

## Stored-procedure contract

Both procedures are **set-based**: each returns a single column of request full-names (the values of
`request.GetType().FullName`). The provider checks membership in memory.

### Unscoped (default)

```sql
-- Anonymous requests: no required parameters.
CREATE PROCEDURE dbo.GetAnonymousRequests
AS
BEGIN
    SET NOCOUNT ON;
    SELECT r.[RequestName]
    FROM dbo.AnonymousRequests AS r;
END;

-- Allowed requests for a user: receives @UserId.
CREATE PROCEDURE dbo.GetAllowedRequestsForUser
    @UserId NVARCHAR(128)
AS
BEGIN
    SET NOCOUNT ON;
    SELECT ra.[RequestName]
    FROM dbo.RequestAccess AS ra
    WHERE ra.[UserId] = @UserId;
END;
```

### Scoped (shared AuthZ database)

When `ServiceName` / `ApplicationName` are configured, the provider also passes `@ServiceName` /
`@ApplicationName` (names configurable) to **both** procedures:

```sql
CREATE PROCEDURE dbo.GetAnonymousRequests
    @ServiceName NVARCHAR(128),
    @ApplicationName NVARCHAR(128)
AS
BEGIN
    SET NOCOUNT ON;
    SELECT r.[RequestName]
    FROM dbo.AnonymousRequests AS r
    WHERE r.[ServiceName] = @ServiceName
      AND r.[ApplicationName] = @ApplicationName;
END;

CREATE PROCEDURE dbo.GetAllowedRequestsForUser
    @UserId NVARCHAR(128),
    @ServiceName NVARCHAR(128),
    @ApplicationName NVARCHAR(128)
AS
BEGIN
    SET NOCOUNT ON;
    SELECT ra.[RequestName]
    FROM dbo.RequestAccess AS ra
    WHERE ra.[UserId] = @UserId
      AND ra.[ServiceName] = @ServiceName
      AND ra.[ApplicationName] = @ApplicationName;
END;
```

## Caching trade-off

Caching avoids a database round-trip per request, but a cached allow **or** deny set stays in effect until the
entry's TTL expires. After a user's access is revoked (or rules change in the database), authorization may
therefore continue to use the **previous** decision until `AnonymousCacheDuration` / `UserCacheDuration`
elapse for that cache key. This is an intentional performance trade-off with a practical security impact.

Keep `UserCacheDuration` short (the 1-minute default is a reasonable starting point) and set
`EnableCache = false` when immediate revocation is required.
